# Анимации окон и разделов Windows

Оба оформления используют `ui-motion.js` и `ui-motion.css`.

- Диалоги и фон: вход 220 мс, выход 170–220 мс, прозрачность и небольшой
  сдвиг с масштабированием. Используются нативные discrete display/overlay
  transitions: JavaScript не задерживает закрытие модального состояния.
- Разделы настроек, аудио, артиста и очереди: scoped View Transitions,
  исчезновение вверх и появление снизу. Последнее быстрое переключение
  отменяет устаревший переход. Имена снимков очищаются после завершения.
- Окно настроек: оверлей гасится по `opacity` и `visibility`, карточка
  приходит из `translateY(10px) scale(.992)`. Время перехода задано один раз
  в `ui-motion.css` (этот файл подключён всегда, его `html body ...` селекторы
  выигрывают у отложенных пакетов); `settings-refresh.css` задаёт только
  состояния, которые интерполируются. Закрытие сразу снимает `pointer-events`
  с оверлея, поэтому клик по соседнему разделу не ждёт конца анимации.
- Контекстные меню: вход и выход 150 мс — `opacity`, `translateY(-6px)` и
  `scale(.97)`; `display` объявлен discrete с `allow-discrete`, а `@starting-style`
  даёт вход без добавления промежуточного класса. В закрытом состоянии
  `pointer-events: none`, поэтому меню не съедает следующий клик
  (`base.css`).
- Выпадающие списки: плавные opacity/transform и discrete display transitions.

При reduced motion переключение выполняется сразу: у контекстного меню,
баннеров и раскрытия загрузок переходы выключены отдельным `@media`
блоком рядом с самим эффектом. `perf-low` и `battery-saver` гасят фоновые
и композитные эффекты через уже существующие правила `base.css`; новые
переходы не добавляют собственных таймеров и не работают в покое.

`tests/ui_motion_browser.cjs` проверяет реальный Chromium в обоих стилях:
закрытие освобождает клики, повторное открытие остаётся открытым, при быстрых
переключениях побеждает последний запрос, меню удаляются, reduced motion
не задерживает обновление. Нативное окно NeDotify не запускается.

### Базовый переход кнопок и почему он был причиной «дёрганья»

`base.css` объявляет один общий переход для `button`, `.icon-btn` и `.play-btn`
с `!important`. Это осознанная база: она задаёт нажатие и смену цвета всем
кнопкам сразу. Проблема была в списке свойств — он содержал только `transform`,
`opacity` и `background`. Любая компонентная кнопка, которая объявляла свой
`transition` (например, морфинг play/pause меняет `width` и `border-radius`),
молча теряла эти свойства, потому что `!important`-правило перекрывало шорткат.

Теперь базовый список включает `background-color`, `color`, `border-color` и
`box-shadow`. Компоненты, которым нужны собственные свойства (`width`,
`border-radius` у `#pp-btn-play`), дописывают их в своё `!important`-правило.
Стоимость не изменилась: те же свойства, тот же один слой на кнопку, эффект
только при взаимодействии.

Список проверенных конфликтов каскада
(`docs/audits/remediation/CSS_CONFLICT_ALLOWLIST.json`) обновлён вместе с
правками: 225 записей, все классифицированы как условные или state-override,
безусловных конфликтов нет. Это пинит `tests/test_frontend_css_wiring.py`.

### Строки списков не имеют входной анимации

У `.track-item` нет `animation: fadeIn`. Раньше она была, и каждый ререндер
списка — порция потокового поиска, `queue_updated`, обновление хвоста «Моей
волны» — переигрывала её сразу для всех строк: именно это выглядело как мигание
списка. Новые строки проявляет `NeDotifyMotion.reveal` (или `settleList` для
сдвига), а переиспользованные узлы не анимируются вовсе.

| Поток | Механизм |
| --- | --- |
| Поиск | Результаты только дописываются; порядок ранжируется один раз по `__completion__`, поэтому префикс списка стабилен и перерисовки нет. |
| Очередь | Узлы переиспользуются по `entry_id`; смена трека и перестановка двигают живые строки, а маркер `playing` применяется на месте. |
| «Моя волна» | Если сигнатура переранжированного списка не изменилась, DOM не трогается. |
| Главная | Секции пропускаются по сигнатуре; догрузка обложек правит `src` у живых карточек. |
| Загрузки | Строки keyed по `track_id`, прогресс идёт через `transform: scaleX()`. |
| Настройки текста | Типографика — четыре переменные на `:root`; перезамер листа кинетики один раз на кадр, а не на каждое движение слайдера. Значения уходят в SQLite (`lyrics_display`) одним dict и восстанавливаются при старте; `localStorage` — только быстрый кэш для первого кадра. |
