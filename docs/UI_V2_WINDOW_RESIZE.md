# Размер окна и Windows 11 Snap Layouts

Изменения от 15 октября 2026 года. Единственный рабочий интерфейс — `ui/web_new_v2/`.

## Что изменено

- Восемь невидимых областей по краям и углам запускают системное растягивание окна. Основное содержимое остаётся доступным для мыши. В мини-режиме области скрыты.
- `begin_window_resize` проверяет направление и состояние окна, затем ставит ReleaseCapture/WM_NCLBUTTONDOWN в очередь UI-потока. JS-мост возвращается до начала системного цикла изменения размера; вызовов `_emit` внутри операции нет.
- Исправлены числовые Win32 HT-коды, размер LRESULT и перевод экранных координат в клиентские. Учтены отрицательные координаты мониторов и изменение DPI.
- `SnapLayouts` включает WS_THICKFRAME, WS_MAXIMIZEBOX и WS_SYSMENU после установки обработчика. WM_NCCALCSIZE сохраняет полную клиентскую область без стандартной рамки; при нативном разворачивании используется рабочая область текущего монитора.
- Кнопка разворачивания возвращает HTMAXBUTTON. Системные сообщения наведения, нажатия и команд передаются исходному WndProc; Win+Z не перехватывается в JavaScript и не добавляется в таблицу горячих клавиш.
- Координаты кнопки обновляются при resize, изменении её размеров и готовности моста. Ограниченные повторы учитывают позднее создание HWND. Скрытая кнопка очищает прежнюю область Snap.
- Повторная установка обработчика безопасна; при ошибке выполняется откат. Callback сохраняется, пока его использует Windows.

## Адаптивность

Сохранён минимальный размер 600×640. В узком окне основной плеер перестраивается в одну колонку с вертикальной прокруткой; нижняя панель остаётся отдельно. Исправлены расширение главной страницы из-за canvas статистики, размеры горизонтальных подборок и обрезание колонок/элементов управления плеера. Canvas перерисовывается при resize без нового запроса к бэкенду. Группа настроек и профиля снова располагается после растягиваемого разделителя боковой панели.

## Проверки

152 проверки pytest прошли: `test_window_resize_api`, `test_snap_layouts`, `test_emit_thread_safety`, `test_player_layout_geometry`, `test_frontend_js`, `test_frontend_css_wiring`, `test_api_misc`, `test_settings_palette_ui`, `test_profile_view_ui`, `test_library_view_ui`, `test_search_discovery_ui`, `test_sidebar_rail`.

Три headless-проверки Playwright прошли: восемь направлений и доступность содержимого; повтор регистрации Snap и скрытая кнопка; непрерывное изменение размеров шести экранов. Всего 90 состояний: Главная, Поиск, Библиотека, Профиль, Настройки, Плеер, по 15 переходов размеров. Проверены переполнение по горизонтали, наложения нижнего плеера и границы колонок. Скриншоты: `docs/screenshots/ui-v2-resize-20261015/`, четыре размера каждого экрана — 600×640, 900×700, 1100×800, 1600×1000. Использованы тестовые данные и подменённый мост, а не пользовательская библиотека.

## Ограничения проверки

Настоящее приложение по просьбе пользователя **не запускалось**, EXE не собирался. Реальный жест растягивания, отрисовка WebView2 после изменения стилей, системный flyout по наведению и Win+Z ещё требуют проверки в настоящем окне Windows 11. Автотесты проверяют код, порядок Win32-вызовов и адаптивный HTML, но не заменяют эту проверку.

Snap Layouts должны быть включены в настройках многозадачности Windows. Минимум 600×640 ограничивает размещение в более узких/низких зонах, в частности в некоторых четвертях экрана; совместимость со всеми вариантами макетов не заявляется. Microsoft рекомендует ширину не более 500 effective pixels для распространённых зон.

Первичные источники: [Snap Layouts для Win32](https://learn.microsoft.com/en-us/windows/apps/desktop/modernize/ui/apply-snap-layout-menu), [клиентская область окна без стандартной рамки](https://learn.microsoft.com/en-us/windows/win32/dwm/customframe).
