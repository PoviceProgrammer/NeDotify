# Профиль v2 — 15 октября 2026

Профиль переработан по пользовательскому макету: крупный аватар, имя и редактирование; четыре показателя; две колонки с топом, последними прослушиваниями, обложками недавней музыки и плейлистами. На небольшом окне колонки становятся одной, карточки музыки прокручиваются горизонтально. Используются существующие цветовые переменные и выбранный фон; глобальные цвета и настройки не переопределяются.

Редактирование имени использует прежний ключ `personalization.nickname`. Аватар выбирается через существующий `select_avatar` и отображается через прежний loopback-маршрут с токеном; при недоступности изображения остаётся локальная иконка. Диалог поддерживает клавиатуру, Escape, отмену и повтор после ошибки сохранения.

## Данные и ограничения

- «Прослушиваний» — `get_wrapped_stats('all').total_plays`. Старое `get_profile_stats().total_tracks` означает количество записей музыкальной библиотеки, поэтому при отсутствии счётчика истории оно показано с подписью «Треков в библиотеке».
- Время — существующий `total_listening_time_ms`, без подмены оценочным временем Wrapped. Избранное и число плейлистов — реальные поля профиля.
- Топ за всё время сохраняет существующий `most_played` / `play_count`; неделя, месяц и год используют готовый `get_wrapped_stats(period)` / `plays`. Ответы ранее выбранного периода не заменяют новый топ. Старый API Wrapped при внутренней ошибке возвращает пустую статистику, поэтому такую ошибку невозможно полностью отличить от пустого периода на стороне UI.
- Последние действия — последние прослушивания. API возвращает до пяти уникальных треков с последним временем каждого; это не полный журнал событий и не история создания плейлистов. Диалог «Показать все» прямо поясняет объём доступных записей. SQLite-время трактуется как UTC, отсутствующие отметки времени не выдумываются.
- Дата регистрации отображается только из сохранённого поля. Прежнее автоматическое создание сегодняшней даты при открытии страницы удалено. Уже сохранённые даты не переписываются.
- «Ваши плейлисты» содержит избранные треки и существующие пользовательские плейлисты. API не предоставляет признак любимого плейлиста. Поддержаны открытие коллекции, воспроизведение, переход к полному списку, создание обычного плейлиста и прежняя команда создания плейлиста из локальных треков.
- Пользовательские обложки библиотеки используются и в профиле. Иначе показывается коллаж треков или локальная иконка. Закреплённый трек сохранён.

Обновление происходит при открытии профиля, событиях плеера и изменении коллекций; дополнительно раз в 30 секунд, только когда профиль и документ видимы. Протокол моста, Python, база и алгоритмы плеера в этой работе не менялись.

## Проверка

73 профильных pytest-теста прошли: JavaScript, CSS, независимость UI, библиотечный API, очередь, рекомендации, защита от самовольного включения старых цветов, нормализация ID истории и дат. Все шесть браузерных сценариев прошли. Проверены четыре размера (600×640, 900×700, 1100×800, 1600×1000), светлая тема, редактирование, отмена выбора аватара, периоды, воспроизведение, плейлисты, пустые состояния, отказ с повтором и устаревшие ответы. Дополнительный сценарий проверяет аватар через тестовый proxy-маршрут, длинное имя, reduced motion и непрозрачный вариант без backdrop-filter.

Скриншоты находятся в `docs/screenshots/ui-v2-profile-20261015/`. Все данные и изображения в проверках демонстрационные. После запрета пользователя приложение не запускалось; работа с реальной библиотекой и системным диалогом выбора аватара в pywebview не проверялась. EXE не собирался. Оригинальный ZIP-бекап v2 не изменялся.
