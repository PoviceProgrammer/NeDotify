# Windows: выбор артистов и «Моя волна»

Изменения только в исходниках Windows. Новый EXE по просьбе пользователя не собирался.

## Поведение

- Свёрнутый sidebar: кнопки центрируются в доступной ширине, исправлены отступы нижнего профиля в macOS-оформлении.
- Шаг артистов в преднастройке: круглая сетка из 20 артистов с двух пользовательских скриншотов, никами и настоящими фотографиями каталога. Файлы лежат в `ui/web_new_v2/assets/onboarding-artists`, происхождение записано в `sources.json`. Загрузка двадцати фотографий при каждом старте не требуется.
- Поиск не ограничен быстрым списком: используется существующий общий поиск исполнителей YouTube/Deezer. Есть debounce 300 мс, идентификатор запроса, отбрасывание устаревших ответов, объединение дублей, поиск без учёта регистра/ё и понятное состояние сетевой ошибки. Поисковый результат вне списка сохраняется наравне с быстрым выбором.
- Выбор минимум трёх артистов перед завершением настройки сохраняется в `personalization.favorite_artists`, восстанавливается при повторном открытии и задаёт начальные сигналы рекомендаций. «Настроить позже» остаётся доступным. При пустой истории выбранные артисты заменяют общие начальные предпочтения.
- На главной отдельная секция «Моя волна» перед «Для тебя». Она запрашивает до 100 подходящих треков. Если доступно меньше 60, показывается реальное количество и возможность повторить загрузку; дубликатами или выдуманными треками объём не дополняется.
- Обычная строка трека получает весь список волны и свой индекс через существующий `createTrackElement` → `play_track`. Нажатие переключает очередь целиком на волну и начинает с выбранной песни.
- При смене трека, лайке или явной обратной связи будущая часть активной волны пересчитывается. Существующий профиль учитывает измеренную длительность прослушивания, завершённые прослушивания, ранние пропуски, любимые и нежелательные треки/артистов. Проигранная часть исключается из новой подборки.
- `replace_personal_wave_tail` сохраняет текущий объект трека и прошедшую часть очереди. Перед заменой проверяются session token, entry ID и revision. Запоздавший результат не заменяет другой плейлист. Старая часть очереди ограничена 100 записями, чтобы длительная волна не накапливала неограниченную историю в памяти.

## Исправленные ограничения

Старый ranker имел жёсткую границу 50. Для персональной волны добавлена отдельная ёмкость 100; обычные подборки сохраняют прежний предел. Общий видеопоиск давал много результатов без исполнителя, и фильтр оставлял 0–23 записи. Для большой волны добавлен музыкальный `songs_only` фильтр YouTube, с более широким поиском по выбранным артистам. Уверенность повышается только при подтверждённом совпадении указанного в каталоге исполнителя с выбранным артистом.

Существующая инфраструктура рекомендаций сохранена: локальные сигналы → каталог/радио → проверка пригодности → ранжирование → очередь. Для сравнения изучен [re-com](https://github.com/umsachde/re-com), который также объединяет radio/related/artist signals. Его код и дополнительные зависимости не переносились.

## Проверки

- Браузерный стенд `tests/onboarding_preferences_browser.cjs`: 20 быстрых карточек; Radiohead вне списка; сохранение выбора; повторное открытие; мобильная ширина 360 px; центрирование кнопок свёрнутого macOS sidebar с допуском 1 px. Успешно.
- Настоящий поиск YouTube: Radiohead найден вместе со связанными исполнителями.
- Настоящая генерация в пустом временном профиле: три артиста (9mice, Heronwater, KAI ANGEL) → **82 трека**; шесть выбранных артистов → **100 треков**. Пользовательские cookies, история и ключи не использовались.
- Новые backend/queue/UI tests покрывают большой пул, исключение проигранного, обновление после dislike, сохранение текущей песни, отказ при смене очереди, весь список и выбранный индекс в строке трека, request ID и revision.
- Нативный стенд `tools/bench/check_personal_wave_native.py` запускает исходники в отдельном пустом профиле. Проверяет настоящую секцию, минимум 60 строк, переключение очереди с выбранной позиции, соответствие названия и продвижение реальных аудиочасов. Выход muted; слышимость не оценивается.
- Промежуточный полный прогон: 2834 passed и одно замечание CSS-gate; замечание устранено адаптивной сеткой без конфликтующего media override. Последующая целевая проверка: 115 passed. Окончательный результат полного прогона записан в `.test_runs/personal-wave-verified-20261109.txt`.

**Финальный полный прогон: 2836 passed, 9 skipped, 2 network deselected (140.10 с).** Повторная нативная проверка после выбора артистов: 77 строк в секции, очередь из 77 треков, выбранный индекс 3, название играющей композиции совпало с нажатой строкой, реальные аудиочасы продвигались. Артефакт: `tools/bench/results/windows-native-live-20261109-210529/result.json`; рядом `personal-wave.png`. Браузерная проверка преднастройки/поиска/центровки также прошла.

Изменения ещё не проверялись многочасовым прослушиванием. Доступность минимум 60 реальных записей зависит от каталога и сети; недостаточная выдача показана явно. Качество персонализации будет уточняться с накоплением настоящих измеренных прослушиваний, а не по искусственной истории.
