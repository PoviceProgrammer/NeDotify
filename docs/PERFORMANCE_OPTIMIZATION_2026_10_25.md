# Оптимизация Windows-приложения, 25 октября 2026

Изменения сохраняют качество эффектов, DPR, настройки FPS и поведение очереди.
Профиль пользователя не использовался: тесты и WebView работали с временными
базами и сгенерированными треками. Подробные числа: рядом в
`PERFORMANCE_OPTIMIZATION_2026_10_25.json`.

## Реализованные изменения

1. **LUFS:** постоянная очередь изменённых файлов, один рабочий поток,
   обработка небольшими порциями, уступка времени между секундами декодирования.
   Редкая сверка файлов сохраняется; замена файла по прежнему пути проверяется
   по времени изменения и размеру. Отмена не публикует неполный результат.
   Метод расчёта громкости и анализируемые аудиосэмплы сохранены.
2. **Waveform:** скрытые страницы не рисуются; геометрия Path2D переиспользуется
   для двух заливок и обновлений прогресса. Открытие страницы на паузе,
   восстановление окна, смена размера и DPR вызывают перерисовку.
   Начальная прозрачность анимации появления не подавляет рисунок.
3. **Библиотека:** виртуальный список сохраняет полную коллекцию отдельно от DOM,
   монтируя видимые строки с запасом. Фокус и перетаскиваемая строка удерживаются,
   выбор и состояние загрузки восстанавливаются при возвращении строки.
   Высота измеряется без влияния масштабирования анимации; сохранены промежутки
   между строками, явная кнопка «Показать ещё» и полная очередь воспроизведения.
4. **Сводка библиотеки:** компактный API счётчиков и идентификаторов избранного
   вместо полной загрузки объектов. Старый API остаётся запасным вариантом;
   локальное избранное дедуплицируется. Коллаж запрашивает только четыре трека.
5. **Офлайн-пагинация:** компактный индекс доступности и чтение метаданных только
   нужной страницы. Проверки диска не держат общий write lock базы. Изменение
   БД/каталогов инвалидирует индекс; повторная сверка содержимого — через 30 с.
   Каждый возвращаемый файл перепроверяется; исчезнувшие файлы не оставляют дыр
   в странице. Воспроизведение отдельно проверяет доступность файла.
6. **FTS:** изменение счётчика прослушиваний или LUFS больше не перестраивает
   поисковый индекс. Обновление реально изменившихся индексируемых полей
   сохраняет синхронизацию поиска; старый триггер мигрируется.
7. **Старт UI:** обработчики и каталоги панели настроек вынесены в отложенный
   модуль, а восстановление оформления осталось в раннем коде. Первый ввод
   сохраняется, Tab/Escape/набор текста работают нативно, pagehide отменяет
   запланированную инициализацию. Lyrics/equalizer/queue загружаются параллельно
   после первой отрисовки иконок, с прежним порядком регистрации и replay событий.
8. **Повторная работа:** backfill истории/LUFS выполняется однократно через
   версии миграций; новые иконки обрабатываются в пределах добавленных строк
   и контейнеров, без повторного обхода всей страницы.

Прокрутка измерена в настоящем WebView2: один запуск на версию, два прохода
вниз/вверх, 2000 треков, одинаковая высота прокрутки 112280 px. Настройки
анимации и FPS не снижались. CPU за секунду почти тот же при удвоенной частоте
кадров; это не доказательство снижения CPU при любой нагрузке. RSS включает
Python и дочерние процессы WebView и зависит от среды. Загрузка GPU аппаратными
счётчиками не измерялась; подтверждено устранение лишних вызовов рисования.

Пустой LUFS poll по базе с 2000 треков: 20 инструкций SQLite VM и 0 проверок
файлов после первичной сверки. Это не включает редкий полный проход сверки.
Ранний `settings.js` уменьшился примерно на 85,9 КБ (47%). В трёх тёплых
запусках медиана готовности UI после reload составила 325,6 → 300,8 мс;
время появления окна осталось около 1,9 с. Эти короткие серии не доказывают
устойчивого ускорения полного старта на любой машине.

## Проверка интерфейса и ограничения

Нативная проверка списка при DPR 1 и 2 прошла: середина, последний трек,
возврат наверх, удержание фокуса и выбор после повторного монтирования.
Одновременно было смонтировано 12–26 строк. Сравнение старого и нового
Canvas-рендера на 108 комбинациях стиля, размера, позиции, hover и DPR дало
точное совпадение каждого пикселя (максимальная разница каналов — 0).
После стабилизации захвата все 24 скриншота прошли исходный pixel guard:
три темы × четыре экрана × DPR 1/2, viewport 1280×800. Допуск не расширялся:
разница канала до 2/255 и не более 0,025% отличающихся пикселей.

Во время работы другой процесс изменял HTML/CSS и код мини-плеера. Эти правки
сохранены. Для сравнения именно оптимизаций использовалась отдельная копия
исходного UI с нашими изменениями; рабочая папка не откатывалась. Изменения
внешнего дизайна не следует приписывать этой оптимизации.

Инструмент проверки исправлен: он ожидает завершения инициализации UI,
использует нативный CDP WebView2 при недоступном TCP-порте, завершает конечные
анимации перед скриншотом, не ждёт скрытые lazy-изображения и сохраняет ошибки
сценария. Для скриншотов ответы lyrics фиксированы, чтобы сетевой таймаут не
выглядел визуальной регрессией. Canvas повторно рисуется после завершения
изменения viewport/DPR. Эти изменения относятся только к инструментам проверки.

Полный прогон запускается командой:

```powershell
& '.venv_win/Scripts/python.exe' -m pytest -q --tb=short
& '.venv_win/Scripts/python.exe' tools/check_source_manifest.py
```

Известное исходное падение `test_base_refresh_conflicts_match_the_reviewed_allowlist`
воспроизводилось до наших изменений: CSS allowlist не соответствует правилу
`#main-content` в `base.css`. Allowlist не перезаписывался для сокрытия ошибки.

На согласованном этапе полного прогона было 1838 успешных тестов и только это
исходное падение. После последующих параллельных изменений рабочей папки
финальный полный прогон дал **1856 passed, 5 failed, 9 skipped, 1 deselected**.
41 целевой тест оптимизаций на этой же текущей папке проходит. Пять оставшихся
ошибок не скрыты и не исправлялись откатом чужой работы:

- `test_feature_controls_ui`: удалённая параллельно функция `applyOfflineState`;
- три проверки `test_lazy_service_deadlock`: тестовый `_Component` не имеет
  нового метода `auto_update_in_background`, вызываемого из `AppCore`;
- `test_listening_comparison`: изменённое преобразование ошибки `offline`.

Поэтому результат визуальной проверки относится именно к согласованному
снимку оптимизаций, а не является утверждением, что любые одновременно
внесённые изменения всего приложения прошли проверку.
Артефакты запусков находятся в `%TEMP%/NeDotify/optimization-20261024/`.
