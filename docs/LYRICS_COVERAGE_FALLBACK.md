# Lyrics and timing coverage: practical fallback notes

Date checked: 2026-10-28. This note is based on provider/API documentation, upstream source, and the current NeDotify lookup flow. It does not estimate catalog hit rates.

## Recommendations

1. **Keep the existing provider cascade, but distinguish text from timing quality.** LRCLIB/plain lyrics and ordinary LRC can provide text/line timing; they cannot supply genuine word timestamps. Keep progressive publishing and the current identity/version/duration checks. Never call catalog coverage universal: providers have separate catalogs and miss on tracks, editions, languages, and regions.
2. **Use Better Lyrics QQ as a bounded word-timing fallback.** The existing Better Lyrics request calls `/getLyrics` (TTML); official docs expose `/qq/getLyrics`, returning QRC with word timing and no API key requirement for cache misses. It has a different response shape (`lyrics`, `provider`) and an exact cache key without duration tolerance or stale fallback. Make at most one QQ call after the current Better Lyrics result is unusable, parse QRC, then pass through existing strict identity and duration checks. [Endpoint contract](https://docs.betterlyrics.org/reference/get-lyrics), [provider matrix](https://docs.betterlyrics.org/docs/providers).
3. **Fix Unison video-ID miss fallback.** Current `RichLyricsProviders.unison` chooses the video-ID endpoint whenever a valid ID exists, returns on any miss, and refuses title fallback forms when `fallback=True`; it never retries Unison with song/artist after an ID miss. Do one title+artist(+album/duration) lookup after the exact ID misses, verify returned identity/version/duration, and keep fallback titles subject to the existing downgrade rules. Unison documents both video-ID and metadata lookups. [Unison API](https://docs.betterlyrics.org/unison), [local provider](../services/lyrics_providers.py), [lookup cascade](../services/lyrics_lookup.py).
4. **Treat local ASR as a last-resort, explicitly generated transcript.** `faster-whisper` supports word-level start/end timestamps (`word_timestamps=True`) and CPU `int8`. The project's Python 3.14 environment is viable at the binary-dependency level: PyPI has Windows CPython 3.14 wheels for CTranslate2 and PyAV. However, the latest PyPI `faster-whisper` release may not include the merged PyAV 19 fix; pin `av<19` with that release, or use a pinned upstream commit containing the fix, then verify on the packaged runtime. The app's `.venv_win` currently has none of `faster-whisper`, `ctranslate2`, or `av`; no `whisper.cpp` binary/model was found in the project tree. [faster-whisper usage and CPU benchmark](https://github.com/SYSTRAN/faster-whisper), [CTranslate2 wheels](https://pypi.org/project/ctranslate2/), [PyAV wheels](https://pypi.org/project/av/), [upstream PyAV 19 fix](https://github.com/SYSTRAN/faster-whisper/issues/1589).
5. **For a lower-dependency Windows fallback, evaluate the official whisper.cpp CPU release binary.** Upstream publishes Windows binaries and documents experimental word-level timestamps with `-ml 1`. The release workflow builds x64; model weights are a separate download. Faster-whisper's official benchmark reports small-model CPU int8 at 1m42s for 13 seconds of audio on an i7-12700K, so don't promise interactive latency on ordinary PCs. ASR can hallucinate/miss lyrics: one Whisper singing study measured mean WER 0.56 across its Schubert dataset, with large variation by song/version. Accept only plausible output, mark it as generated, and retain a retry/provider path. [whisper.cpp release](https://github.com/ggml-org/whisper.cpp/releases), [word timestamps](https://github.com/ggml-org/whisper.cpp#word-level-timestamp-experimental), [faster-whisper benchmark](https://github.com/SYSTRAN/faster-whisper), [singing evaluation](https://aclanthology.org/2024.nlp4musa-1.3/).

## Python 3.14 compatibility detail

The faster-whisper source declares Python `>=3.9`, and CTranslate2 4.8.4 publishes a Windows `cp314-win_amd64` wheel. But the older PyPI faster-whisper code passes `metadata_errors` to `av.open`; PyAV 19 removed that parameter. Upstream merged a compatibility fix, while PyPI version availability is separate from the GitHub `master` source. For reproducible packaging, pin a tested set: either `faster-whisper` release + `av<19`, or a pinned post-fix commit + compatible PyAV. The project's `.venv_win` currently has no ASR stack installed.

## Coverage limit

No source documents a guarantee of universal Russian lyrics or timing coverage. Catalog APIs can miss; Whisper is trained/evaluated principally for speech and has substantial singing transcription errors. Present the cascade as best-effort: verified catalog lyric first, line-synced text if that is all a source provides, and clearly identified generated ASR as the last resort. Do not turn line timing into invented word timing.
