# Живое воспроизведение трёх источников — 10.11.2026

## Результат

YouTube, SoundCloud и вкладка Spotify прошли реальное воспроизведение в
Windows-приложении на текущем коде через Python/pywebview/WebView2. Для каждого
источника взяты два трека из настоящего поиска; каждый сценарий повторён в
оформлениях current и macos (6 сценариев, 12 запусков треков).
Продуктовые API, провайдеры, потоковый proxy и HTML5 Audio не подменялись.

| Источник | Поисковый запрос | Подтверждённое аудио | Оба оформления |
|---|---|---|---|
| YouTube | Rick Astley | googlevideo.com | пройдено |
| SoundCloud | v3lvet | playback.media-streaming.soundcloud.cloud | пройдено |
| Spotify (название вкладки) | Radiohead Creep | googlevideo.com | пройдено |

SpotifyService в этом продукте использует публичный каталог iTunes и подбор
полного аудио в YouTube с проверкой записи. Это проверенный путь вкладки
Spotify, а не прямое воспроизведение DRM-аудио серверов Spotify.

## Что проверяет сценарий

- `AppApi.search` и реальные события search_results/search_completed.
- `AppApi.play_track`, очередь ровно из двух результатов, собственный HTTP proxy.
- Настоящий HTMLAudioElement: currentTime движется, readyState>=3,
  нет паузы/буферизации. Через 1,5 с часы каждого трека продвинулись >700 мс.
- AnalyserNode существующего Web Audio графа показывает ненулевой PCM-пик.
- Реальная кнопка паузы останавливает часы, продолжение меняет состояние на playing;
  seekTo(30000) подтверждён часами >=29,5 с и снятием seeking/buffering.
- next_track запускает второй результат без замены очереди; его часы и сигнал
  проверяются так же, как для первого.
- Фактические hostname результатов AudioEngine.resolve_stream_url записываются
  наблюдателем, не меняющим результат функции. Для SoundCloud проверяется
  собственный медиадомен, поэтому YouTube fallback не засчитывается как прямой SC.

Временный профиль начинается с пустой библиотекой, без cookies и Last.fm ключа.
Для измерения PCM выход analyser отключён от speaker destination; реальные
декодер и граф работают, звук не транслируется в колонки. Физический аудиовыход
не оценивался. VPN Happ не отключался и не перенастраивался. Zapret в профиле теста
выключен. Глобальные библиотеки, маршруты и очередь пользователя не менялись.

## Найденный и исправленный дефект

Реальный второй результат iTunes — `Creep (feat. Radiohead) [Very 2021 Rmx]`,
Thom Yorke, 542 с. YouTube возвращает ту же запись как
`Creep (Very 2021 Thom Yorke Rmx)`, Radiohead/Thom Yorke, 543 с.
Старый same_recording отклонял её из-за точного сравнения полного названия
ремикса, и следующий трек из очереди не запускался.

Добавлено узкое сопоставление: разрешено одностороннее добавление общего
подтверждённого artist credit в скобки именованного ремикса. Название/год микса,
исполнители и допуск длительности сохраняются. Generic Remix не считается
достаточным доказательством; разные миксы, годы, чужие ремиксеры и длительности
по-прежнему отклоняются. Не удаляются имена на обеих сторонах одновременно.

Регрессия `tests/test_recording_remixer_credit.py`: до исправления
**1 failed, 6 passed**, после исправления совместно с matching/resolver/recovery
**162 passed**. Отдельные контракты воспроизведения/proxy/SoundCloud:
**206 passed** (предварительный прогон до изменения matcher).

## Неуспешные попытки сохранены

Первый расширенный сценарий ошибочно вызывал API play_pause для переключения;
этот метод только читает состояние. Диагностика исправлена на настоящую кнопку
плеера; код продукта ради этого не менялся.

Предварительные прогоны в 09:29 и 12:31 имели сетевой timeout/DNS-отказ. Они не
выдаются за успех. Повтор на отдельном профиле подтвердил воспроизведение
акустической версии, но стабильно отвергал указанный ремикс. Минимальная проба
`.test_runs/spotify-remix-probe.log` показала matches=false при совпадающих
исполнителях/длительности; это стало регрессионным тестом. После исправления
изолированный Spotify и полный сценарий успешно завершились.
