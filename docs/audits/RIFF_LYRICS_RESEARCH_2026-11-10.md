Проверено 10 ноября 2026 года по GitHub API и исходникам, закреплённым на SHA. Анализ относится только к Windows-приложению NeDotify. Исходники приложения, профиль, VPN и сборки не менялись; тексты песен не загружались для проверки покрытия.

## Что действительно изменилось

1. **Автоматический выбор нескольких источников включён по умолчанию.** На сервере и в клиенте default `lrclib` заменён на `auto`. Явный выбор `lrclib` теперь оставляет только этот источник. В `auto` порядок: LRCLIB → Genius → Musixmatch → Kugou → NetEase → сохранённый plain fallback. Раньше Genius вызывался последним и только при отсутствии накопленного plain текста. Это расширение маршрута получения текста, а не новая база песен. Если Genius вернул plain, последующие источники уже не запрашиваются: порядок не гарантирует максимальную точность синхронизации. [Сервер](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L6514-L6516), [каскад](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L6613-L6688), [клиентский default](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/renderer/app.js#L7502-L7505).
2. **Усилен Genius.** Основной endpoint теперь `/api/search/multi`, при отсутствии результатов — `/api/search/song`; учитываются URL с окончанием `-lyrics`. Страница загружается с обработкой перенаправлений. Удаляются исключённые из выделения блоки, Contributors/Embed/You might also like, заголовки и повтор целого текста; при miss есть возврат к LRCLIB. Это конкретная доработка discovery и extraction. Однако ranking Genius всё ещё удаляет кириллицу через `[^a-z0-9]` и допускает первый hit с нулевым score: улучшение русского покрытия этим кодом не доказано. [Genius extraction](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L5859-L5924), [lookup и ranking](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L5927-L6009).
3. **Добавлены клиентские попытки восстановления после miss.** После основного запроса клиент повторяет серверный lookup с очищенными title/artist, затем напрямую пробует LRCLIB `/get`, `/search` и Genius. У Genius есть дополнительные HTML-селекторы и варианты запросов, включая title без artist. Основной таймаут клиента вырос с 4 до 10 секунд; отдельные recovery запросы получают свои таймауты, поэтому 10 секунд не являются общим бюджетом всей операции. [Новый fallback](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/renderer/app.js#L7355-L7478), [вызов и таймауты](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/renderer/app.js#L7513-L7555).
4. **Online lookup теперь разрешён и для локальных/TikTok треков**, когда online lyrics включены. Раньше эти категории принудительно получали `online=0`. **Пустой серверный miss удаляется из кеша**, позволяя повторить поиск; найденный Genius теперь сохраняется и читается с диска. [Изменение online-флага](https://github.com/rootscripts/riff/commit/ab36cf1182127790f36f23e48bc7d482364c8efe), [диск](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L6591-L6607), [запись и miss](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L6691-L6708).

В changelog отдельно заявлены инструментальные паузы и исправление word sync. Это изменения показа/синхронизации. В изученных `server.js` и `app.js` не появился отдельный поиск песни по строке текста (`search/lyric`); новый `fallbackDirectLyricsSearch` ищет текст по названию и исполнителю. [Changelog](https://github.com/rootscripts/riff/releases/tag/v0.7.0), [реализация fallback](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/renderer/app.js#L7355-L7478).

## Сопоставление с текущим NeDotify Windows

| Локальный модуль | Что уже есть | Отличия / полезный пробел |
|---|---|---|
| [`lyrics_service.py`](../../services/lyrics_service.py) | Общий HTTP transport с proxy-настройкой, ограниченный пул, единый вход `get_lyrics`, передача YouTube ID. | Клиентский обход сервиса из Riff дублировал бы наши запросы и транспорт; переносить его целиком не требуется. |
| [`lyrics_lookup.py`](../../services/lyrics_lookup.py) | Параллельный автоматический каскад; общий бюджет 8 с, лимиты запросов, отмена, progressive upgrade plain → line → word/syllable; title/artist/version/duration gates; транслитерация; память/диск; локальные embedded lyrics с дальнейшим online lookup при miss. `not_found` живёт 30 с только в памяти, `unavailable` не кешируется. | Новое `auto` у Riff уже покрыто более широким механизмом. У нашего Genius есть `/search/multi`, но отсутствует резервный `/search/song`; HTML извлекается только по `data-lyrics-container="true"` простой regex до первого `</div>`. Нет очистки служебных блоков и альтернативных селекторов Riff. |
| [`lyrics_providers.py`](../../services/lyrics_providers.py) | Unison, Better Lyrics TTML, SimpMusic по video ID, форматный парсинг и проверка идентичности. | Эти дополнительные источники отсутствуют в рассмотренном каскаде Riff. Новая версия Riff не делает их ненужными. |
| [`lyrics_search.py`](../../services/lyrics_search.py) | Отдельно находит **песню по строке текста** через Genius `/search/lyric`, проверяет snippet, затем подтверждает catalogue identity через YouTube/Deezer. | Это другая операция, чем новый title/artist fallback Riff; прямого нового аналога в изученном upstream нет. |
| [`lyrics_search_service.py`](../../services/lyrics_search_service.py) | Ручной поиск вариантов сразу в LRCLIB, Kugou, NetEase, QQ Music, Genius; ranking, duration, дедупликация, загрузка выбранного текста. | У Genius те же ограниченные HTML-селекторы и нет `/search/song` recovery. Список кандидатов и автоматический lookup используют разный extraction-код — общий parser уменьшил бы риск расхождения. |

Проверяемые локальные точки: `LyricsLookup.accept` (строка 132), `_genius_query` (405), `_ttl`/`_remember` (484/489), `get` и provider jobs (501/715); `LyricsSearchService._search_genius` и `resolve_candidate_lyrics` (345/378). Названия и номера относятся к состоянию файлов во время исследования; исходники являются источником истины.

**Ещё одно различие:** Riff имеет прямой Musixmatch adapter с token и desktop endpoints; в наших lyrics-модулях такого adapter нет. Он существовал до 0.7.0, поэтому его нельзя представлять как находку именно последнего обновления. Статическое наличие адаптера не доказывает доступность API или полезное RU покрытие. [Adapter](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L6130-L6193).

## Практический вывод

Наиболее полезный перенос — **аккуратное восстановление Genius**: общий HTML parser для автоматического и ручного поиска, обработка вложенных контейнеров и служебной разметки, резервный `/search/song` при пустой корректной выдаче `/search/multi`. Всё должно сохранять текущие metadata gates, общий deadline, request cap и cooldown; после rate limit не запускать новые попытки в обход ограничений. Повторы целой песни удалять только при доказанном дублировании контейнеров: совпавшие половины текста могут быть законным повтором куплетов.

Не стоит переносить выбор первого LRCLIB/Genius результата, полное удаление всех скобок из названия или браузерный fan-out. У Riff LRCLIB search выбирает любой synced hit, затем первый результат; frontend Genius принимает первый song URL. Наши version/duration/artist проверки защищают от текста другого издания и должны сохраняться. [LRCLIB selection Riff](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L5815-L5830), [Genius selection клиента](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/renderer/app.js#L7429-L7472), [агрессивная очистка metadata](https://github.com/rootscripts/riff/blob/b5ae2093d8fd07d170b91818919881335959c26c/src/server/server.js#L5758-L5774).

Выводы о коде подтверждены чтением закреплённых исходников и diff 0.6.0 → 0.7.0. Live-покрытие каталогов, сетевые задержки и процент найденных русских песен не измерялись. Автотесты и сборка не запускались: отчёт не меняет выполняемый код.
