# Глубокий аудит Zapret и скачивания YouTube — Windows

Проверка текущих исходников NeDotify Windows 9–10 ноября 2026. Этот отчёт дополняет и заменяет по состоянию кода более ранние краткие проверки Zapret.

## Требования и границы

Проверить интеграцию Zapret целиком: начальную установку, доверие к файлам, аргументы, UAC, владение процессами, параллельные команды, подбор, отмену, обновление, UI/bridge и путь скачивания YouTube. Исправить воспроизводимые ошибки и подтвердить загрузку настоящего аудиофайла. Проекты Android/Linux не изменялись.

VPN не выключался. Happ оставался процессом PID 7288; команды изменения VPN/адаптеров/маршрутов не выполнялись. Реальный winws во время аудита не запускался. Опасные системные операции воспроизводились с подменами, в отдельных тестовых профилях; Job Object проверен отдельно на безвредном дочернем Python-процессе. Личная библиотека и cookies пользователя не использовались.

## Подтверждённые ошибки и исправления

| № | До исправления | Исправление и доказательство |
|---|---|---|
| 1 | Job Object читал `Popen.handle`, которого нет у настоящего Windows Popen; ошибка происходила после создания ребёнка | Используется `_handle`; тест моделирует настоящий интерфейс Popen. Нативная проверка создания/привязки/закрытия Job успешно завершила дочерний Python |
| 2 | Позднее подтверждение UAC могло воскресить отменённый запуск | Поколение запроса сохраняется через UAC и обнаружение PID; запоздалый принадлежащий приложению процесс останавливается; отказ остановки сохраняет PID и честное состояние |
| 3 | Диагностический текст в журнале считался доказательством неудачного запуска даже без установленного PID | После dispatch сохраняется неизвестное состояние и запрет дублирующего запуска, пока нет подтверждения процесса или явного отказа UAC |
| 4 | Исключение сканера после UAC снимало защиту от второго запуска | Защита устанавливается до dispatch и остаётся при неизвестном результате |
| 5 | Общая командная строка могла разрешить остановку чужого процесса с нечитаемым путём | Аргументы только находят кандидатов. Владение подтверждается путём либо UID и временем создания |
| 6 | Унаследованный CWD мог давать владение чужим winws в широкой папке | CWD удалён из правил владения процессами |
| 7 | Неудачный terminate/wait терял живой Popen при отсутствующем PID-файле | Авторитетный handle сохраняется; Job/kill используются как fallback; живой ребёнок не выдаётся за остановленный |
| 8 | Старая проверка падения могла очистить файлы/состояние нового запуска | Проверка поколения и очистка объединены; устаревшее уведомление подавляется |
| 9 | Старый stop, ожидающий глобальную блокировку, мог закрыть Job нового процесса | Поколение проверяется после ожидания; stale-stop не трогает Job нового поколения |
| 10 | Второй выживший PID игнорировался после выхода основного | Liveness проверяет все PID; watcher сохраняет выживших и продолжает наблюдение |
| 11 | Повреждённые списки PID, Infinity, bool и дробные значения могли ломать статус либо превращаться в другой PID | Принимаются только целые PID/их строковые записи в диапазоне DWORD; чтение и запись используют одну нормализацию |
| 12 | При запрете записи PID-файла повышенный процесс терялся для liveness/stop | Идентифицирующая запись сохраняется в памяти текущего экземпляра до успешной записи/подтверждённой остановки |
| 13 | Выключение сбрасывало сохранённую стратегию; неудачный запуск записывал неверный режим | Выключение меняет только enabled; отвергнутая конфигурация не заменяет рабочую |
| 14 | Небулевый bridge-аргумент `"false"` мог включить службу | Небулевые команды отклоняются до системных операций; строковые значения старых настроек нормализуются отдельно |
| 15 | Отложенный автозапуск использовал старый режим и не перечитывал auto_start | Флаги и параметры перечитываются непосредственно в worker |
| 16 | Подбор или явная смена режима могли принять уже работающий процесс с неизвестными аргументами за выбранную стратегию | При подборе и явной пользовательской смене неизвестная стратегия сначала действительно заменяется |
| 17 | Проверка страницы YouTube не доказывала доступность аудио-CDN | После HTTPS-проверок выполняется настоящее скачивание и валидация тестового аудио во временной папке через YouTubeService |
| 18 | Переключение режима повышенного процесса не могло запросить разрешение на его остановку | Для явного пользовательского переключения/подбора разрешён интерактивный stop; фоновая остановка не получает это разрешение |
| 19 | force-update того же тега принимал один exe за полный установленный пакет | Проверяется наличие и PE-целостность всех четырёх обязательных файлов; неполный пакет восстанавливается |
| 20 | Пустая распаковка могла присвоить новую версию старому fallback-exe | Требуется полный staged-пакет в целевой папке; отсутствие файлов не считается установкой |
| 21 | Сбой записи version.json выдавался за успешную установку | Ошибка commit возвращается вызывающему коду; download_finished не отправляется |
| 22 | При неудачном swap оставались новые файлы; при неудачном rollback удалялась единственная резервная копия | Восстанавливается предыдущий набор; новые файлы удаляются; при сбое восстановления сохраняется каталог резервных копий |
| 23 | После pending-update запускался старый путь к exe | Путь повторно определяется после успешной установки |
| 24 | Запуск мог войти в середину замены бинарников, обновление — в середину запуска | Короткая резервация под существующим lock сериализует stop/swap/commit/restart; сетевое скачивание остаётся вне state-lock |
| 25 | Обновление/восстановление могло перезапустить службу после новой команды stop | Перезапуск проверяет поколение, включая атомарную проверку в start |
| 26 | `%VARIABLE%` в одобренном пути переинтерпретировался cmd; `!` зависел от delayed expansion | Опасные percent/quote/CR/LF-пути отклоняются, cmd запускается с `/v:off` |
| 27 | PowerShell-команда установщика содержала буквальные имена переменных вместо URL/пути; неудача WebView2 игнорировалась | Используется штатный `DownloadTemporaryFile` Inno; обязательная зависимость блокирует завершение установки при сбое |
| 28 | Ответ проверки обновлений мог затереть прогресс активного подбора | Прогресс имеет приоритет, пока операция включения не завершилась |
| 29 | Отклонённый короткий POST UI-сервера иногда завершался Windows-reset вместо HTTP 403 | Ограниченное чтение короткого тела до отказа; oversized-body не читается, callback не вызывается; стресс-тест реального loopback |
| 30 | Stop сразу после обнаружения повышенного PID мог восстановить unknown-защиту после подтверждённого завершения | Различаются ещё не отправленный UAC, неизвестный результат dispatch и уже обнаруженный/остановленный процесс |

## Практические ограничения результата

Скачивание YouTube доказано при включённом VPN. Это не является измерением эффективности DPI-обхода на сети пользователя без VPN. Реальные UAC/WinDivert/антивирус/провайдер не проверялись отключением VPN или запуском конкурирующих фильтров. Для этих путей применены регрессионные и системные mock-тесты; нативно проверены безопасные HANDLE/Job-механизмы и запуск окна приложения.

Автоматизация GUI собранного плеера через тестовый DevTools-порт была недоступна; оба Windows UI-инструмента не инициализировали JS kernel (`failed to write kernel assets`, os error 3). Это не выдаётся за успешный UI-тест скачивания. Вместо него отдельно проверены запуск обычного EXE и настоящее скачивание через продуктовый API/менеджер/провайдер в диагностическом frozen-runtime. Скачивание нажатием кнопки в обычном EXE и воспроизведение в его окне в этом прогоне не подтверждены. WebView2-bootstrapper с отсутствующим runtime проверен по коду и компиляцией установщика, без удаления установленного системного runtime.

Наличие тестовой записи на YouTube и поведение внешнего сервиса могут меняться. Успешное скачивание пробы подтверждает этот поток, а не доступность любого возрастного/приватного/регионального видео. При неизвестном результате UAC приложение требует проверки процесса, а не запускает потенциальный дубль.

Глубокий аудит и пройденные проверки дают конкретные доказательства по перечисленным контрактам; они не являются математическим доказательством отсутствия любых будущих ошибок в системе и сторонних компонентах.
