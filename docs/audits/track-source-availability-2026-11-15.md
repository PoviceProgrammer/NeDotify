# Проверка доступности треков в NeDotify для Windows

Дата проверки — 15 ноября 2026 года.

## Поиск

- Локальные треки и офлайн-копии проходят проверку пути, расширения, типа и размера файла. Сам файл при поиске целиком не декодируется. Карточки исполнителей, альбомов и плейлистов показываются без проверки каждой записи. [Поиск](../../core/api.py#L2125) · [Локальная проверка](../../core/offline.py#L14)
- Для сетевых треков явный отказ каталога или свежий отрицательный вердикт резолвера скрывает результат. Явное подтверждение каталога или пригодный кешированный URL позволяет показать трек сразу. Кешированный URL используется как быстрый путь, когда включены YouTube и SoundCloud. Для остальных кандидатов отдельный пул запрашивает URL через движок и добавляет совпадения по мере готовности. Старый запрос не может опубликовать результат после отмены. [Поиск](../../core/api.py#L2125) · [Кеш резолвера](../../core/resolver.py#L88)
- YouTube берёт быстрый вердикт из полей `isAvailable` и `isPlayable`. У SoundCloud `BLOCK`, `SNIP` и `streamable=false` означают отказ, а `ALLOW` с полноценным аудиоформатом даёт положительный вердикт. Положительный результат поиска подтверждает метаданные или возможность получить URL. Сеть и сам файл могут измениться к моменту проигрывания или скачивания. [YouTube](../../services/youtube_service.py#L591) · [SoundCloud](../../services/soundcloud_service.py#L439) · [Движок](../../audio/engine.py#L154)

## Импорт плейлистов

| Вход | Проверка при импорте |
| --- | --- |
| YouTube и SoundCloud | Плоский список через yt-dlp с `extract_flat="in_playlist"` и `download=False`. Пустые элементы и элементы без ID пропускаются. У SoundCloud недостающие метаданные заполняются отдельно. Строка с ID может сохраниться без подтверждения аудиопотока. |
| Deezer | Проверяется полнота постраничной выдачи и устраняются повторные ID. Аудио для каждой записи на этом этапе не проверяется. |
| M3U, JSON, TXT | Распознаются пути, известные поставщики и метаданные. Для текстового названия может сохраниться отложенный запрос `ytsearch1:`. Для существующих локальных аудиопутей БД ставит признак скачанного файла по наличию файла. |

[YouTube](../../services/playlist_import_service.py#L106) · [SoundCloud](../../services/playlist_import_service.py#L176) · [Deezer](../../services/deezer_service.py#L159) · [Парсер файлов](../../services/playlist_import_service.py#L289) · [Транзакция](../../core/database.py#L6332)

`imported_count` показывает число записей, возвращённое транзакцией импорта. Приложение на этом этапе не запускает проверку аудио, которую использует поиск. Это объясняет треки, которые есть в плейлисте, но исчезают из поиска или не играют. [Вход импорта](../../core/api.py#L2467)

**Воспроизведено локально.** Запись с URL страницы LMusic через M3U успешно сохраняется в временную SQLite как `source=local`, без пути к файлу. Движок возвращает `None`, поскольку для локального источника ожидает `file_path` или `url`, а импорт сохраняет ссылку в `source_url`. Внешнюю страницу этот эксперимент не загружал. [Ветка парсера](../../services/playlist_import_service.py#L387) · [Локальная ветка движка](../../audio/engine.py#L169)

**Предлагаемое изменение.** Сохранять состав и порядок плейлиста сразу, а затем проверять дорожки в фоне с ограниченным параллелизмом. Показывать подтверждённые, недоступные и ещё не проверенные записи отдельно по статусу. Таймаут или временный сетевой отказ оставлять повторяемым. Для резерва между источниками использовать сверку исполнителя, названия, версии и длительности через существующее сопоставление записей. [Сопоставление](../../core/playback_recovery.py#L44)

Проверка кода — 64 теста по поиску, импорту, атомарной записи и сопоставлению прошли в Windows-окружении.


## Hitmos и LMusic как источники

- **Hitmos.** Обычный HTTPS-запрос с Windows к указанному URL перенаправился на `rus.hitmos.fm` и вернул HTTP 200 для страницы «5 минут назад» (PHARAOH, Boulevard Depo). Заголовок страницы предлагает прослушивание и скачивание MP3. Публичную документацию API и условия для интеграции каталога в сторонний плеер в доступных материалах Hitmos найти не удалось. [Страница трека](https://hitmos.fm/song/12682699)
- **LMusic.** Та же запись имеет отдельную страницу с кнопками прослушивания и скачивания. Страница указывает 03:42 и 320 кбит/с. Эти значения опубликованы сайтом, аудиофайл не проверялся. Публичную документацию API для стороннего плеера найти не удалось. Разделы 5.2–5.4 соглашения описывают использование штатной функциональности сайта и условия использования за её пределами. Страница авторских прав также ведёт на отдельный лицензионный договор. [Страница трека](https://lmusic.kz/mp3/pharaoh-boulevard-depo-5-minut-nazad/72511) · [Соглашение](https://s3.rs-cont.ru/ruscontent/media/lmusic.kz/files/pdf/user-agreement.pdf#page=3) · [Авторские права](https://lmusic.kz/license)
- **Вариант для NeDotify.** Сначала проверить сценарий «Открыть страницу трека» или добавление скачанного пользователем MP3 в локальную библиотеку. Автоматический поиск, воспроизведение и скачивание через эти сайты стоит проектировать после подтверждения условий интеграции и получения поддерживаемого интерфейса от площадки. Наличие страницы и кнопки скачивания подтверждает веб-сценарий для пользователя. Для автоматической подстановки записи в плейлист нужны отдельные проверки совпадения версии трека и наличия полного аудио.

### Реализовано 2026-11-22: воспроизведение и скачивание вместо браузера

По просьбе владельца треки Hitmos и LMusic теперь **скачиваются и играют** в
приложении; браузер больше не открывается. Изменения:

- `services/web_music_service.py` — `resolve_audio()` читает MP3-адрес, который
  страница Hitmos уже содержит (`play`/`download` в payload Next.js), либо
  открывает страницу трека для id из импортированного плейлиста. Адрес
  принимается только HTTPS, без query/fragment, только с домена площадки
  (`hitmos.fm`, `lmusic.kz` и их поддомены) и только с окончанием `.mp3`; затем
  подтверждается range-запросом, что это действительно MPEG-аудио.
- `core/downloader.py` — `hitmos` добавлен в `_SUPPORTED_SOURCES` и в общую с
  `lmusic` ветку `_fetch_from_provider`, поэтому кнопка «Скачать» ставит файл в
  ту же очередь, что и остальные источники.
- `ui/web_new_v2/js/utils.js` — `webOnly` определяется только флагом
  `external_only`; имя источника больше не отправляет трек в браузер, и
  `hitmos` не выпадает из очереди воспроизведения.

Проверено на живых страницах: поиск `pharaoh boulevard depo` даёт 12 треков,
`resolve_audio` возвращает CDN-адрес (0.1–1.0 с), скачивание дало полный файл
8 869 093 байта с длительностью 221.7 с и прошло проверку
`_downloaded_file_defect`. Тесты: 2 992 прошли, 9 пропущены (2026-11-22).

Ограничение по-прежнему в силе: у LMusic нет публичного API, файл отдаётся
только странице площадки, поэтому при недоступности `lmusic.kz` из сети
пользователя источник отвечает пустым результатом — резервного пути нет.
