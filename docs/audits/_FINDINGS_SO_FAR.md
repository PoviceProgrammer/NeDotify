## 2. P0 — CRITICAL

### F-AR12-1 — Upgrade migration permanently deletes distinct tracks and cascades away their history
- **File:** `core/database.py:313-362` (trigger `:314-315`, destructive DELETE `:344-357`, flag `:358-360`)
- **Confirmed:** yes (reproduced end-to-end on a synthetic "old build" DB)
- **Cause:** a one-shot migration runs whenever `settings.migration_dup_cleanup_done` is absent. It deletes every `tracks` row that is not the lowest id of its `GROUP BY LOWER(title), LOWER(artist)` group. The key ignores `album`, `source`, `source_id`. `PRAGMA foreign_keys=ON` is set on every connection (`:119`) and `history`/`playlist_tracks` declare `ON DELETE CASCADE` (`:194-195`, `:208`).
- **Trigger:** any DB created by a build predating the migration that holds two rows sharing `LOWER(title)`/`LOWER(artist)`. Runs on the UI thread at startup.
- **Impact:** a library row disappears, every play of it vanishes from the history and from the profile statistics, its playlist entries are removed, `play_count` is lost, the audio file stays on disk unreferenced. Not recoverable from the DB. Nothing in the UI reports it.
- **Evidence:**
  ```sql
  DELETE FROM tracks
  WHERE id IN (
      SELECT t.id FROM tracks t
      WHERE t.id NOT IN (
          SELECT MIN(t2.id) FROM tracks t2 GROUP BY LOWER(t2.title), LOWER(t2.artist)
      )
  )
  ```
  Reproduction (temp DB, tracks `Yesterday/Help!` play_count 5 and `Yesterday/Live at Rickenbacker` play_count 9, one history row and one playlist entry each):
  ```
  BEFORE tracks: [(1,'Yesterday','Help!',5), (2,'Yesterday','Live at Rickenbacker',9), (3,'Come Together',2)]
  AFTER  tracks: [(1,'Yesterday','Help!',5), (3,'Come Together',2)]
  AFTER  history: [(1,1,200.0)]          # 9 plays of statistics gone
  AFTER  playlist_tracks: [(1,1,1)]
  ```
- **Fix:** scope the grouping to `(LOWER(title), LOWER(artist), source, source_id)` and only collapse rows with `source_id IS NULL AND file_path IS NULL`; or back the table up (`CREATE TABLE tracks_backup AS SELECT * FROM tracks`) before any `DELETE`. Never delete a row a `history` row points at.
- **Side effects:** a scoped migration leaves genuine duplicates visible in the library — the correct trade-off.
- **Discovered by:** A (AR-12)
