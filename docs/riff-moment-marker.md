# «Лучший момент» — что взято из Riff

Функция уже существовала в NeDotify: SQLite-таблица `track_moments`, мост
`get_track_moment` / `set_track_moment` и метка на трёх шкалах
(`pb`/`pp`/`mp`). Из Riff перенесена не сама идея, а две детали поведения,
которых здесь не было.

Источник: [rootscripts/riff](https://github.com/rootscripts/riff), MIT,
`src/renderer/modules/artist.js` (`getTopMoment`, `setTopMoment`,
`removeTopMoment`, `updateTopMomentPin`) и `src/renderer/modules/ui.js`
(пункт контекстного меню). Код не копировался — перенесена семантика.

## Бэкенда в Riff нет

Важное отличие: Riff хранит метки в `localStorage` под ключом
`riff_top_moments` (`getTopMomentsMap`), серверных методов у него нет вообще —
`src/server/` и `src/main/` не содержат слова `moment`. NeDotify хранит метку в
SQLite, поэтому «унаследовать бэкенд» здесь означает перенести модель ключей
Riff в существующую таблицу, а не заводить новый слой.

## 1. Одна метка — несколько идентичностей трека

Riff пишет одно и то же значение под тремя ключами: канонический id
(`getTrackCanonicalId`), `track.id` и нормализованное `artist - title`
(в нижнем регистре). Чтение перебирает их по очереди, пока не найдёт число.

В NeDotify ключ был ровно один: `["<source>","<source_id>"]` либо
`["id","<row>"]` (`trackMomentKey`). Один и тот же трек приходит в плеер под
разными идентичностями — провайдерский ключ из поиска, строковый id из
библиотеки, — и метка «терялась» при переходе между представлениями.

Перенос: таблица `track_moment_aliases` (`alias_key` → `track_key`).
`get_track_moment` сначала ищет прямое совпадение, затем идёт по алиасу.
Удаление метки сносит и алиасы, иначе они бы её воскрешали. Предел — 12
алиасов на трек (`MOMENT_ALIAS_LIMIT` в `core/api.py` и
`MOMENT_ALIAS_LIMIT` в `core/database.py`): список приходит из UI и не должен
расти с каждым открытым представлением.

Фронтенд собирает алиасы в `trackMomentAliases` (`player.js`) и передаёт их
третьим аргументом `set_track_moment`. Мост отвергает не-список и список с
нестроковыми или пустыми элементами (`_moment_aliases`), а не сохраняет метку,
которую потом никто не найдёт.

## 2. Выбор иконки метки

Riff даёт пять вариантов (`riff_top_moment_icon`: `heart`, `minecraft`,
`honey`, `star`, `fire`) и настройку в интерфейсе.

Перенос: настройка `ui.moment_icon` в `DEFAULT_SETTINGS`
(`core/settings.py`), закрытый набор `MOMENT_ICONS` в `core/api.py`
(`bookmark`, `heart`, `star`, `fire`, `honey`). Значение вне набора
отклоняется в `save_setting` — иначе в UI пришла бы метка без иконки.
`minecraft` не переносится: это пиксельный SVG на ~2 КБ инлайна, ради
которого не стоит держать отдельную ветку.

## Стоимость

- Иконка — статический `mask` на `::before` одной метки, без анимации и без
  собственных таймеров. `bookmark` (по умолчанию) рисуется прежним
  ромбом, поэтому профиль без настроек выглядит как раньше.
- Алиасы — один `JOIN` по первичному ключу при смене трека, не на каждом
  тике позиции. Запись — только по действию пользователя.
- `renderTrackMoment` пишет `dataset` лишь при смене иконки, а не на каждом
  обновлении позиции.

## Тесты

`tests/test_track_moment.py`: метка находится по каждому алиасу, удаление
чистит все идентичности, негодный payload отвергается, набор иконок закрыт.
