# Рекомендации Windows — 2026-11-04

Реализованы четыре согласованных улучшения. Алгоритм группировки ежедневных миксов не менялся.

## Пользовательские сценарии

- **Непрерывная волна:** существующая команда «Волна по треку» запускает исходный трек и автоматически дополняет очередь порциями до 15 треков, когда остаётся не больше пяти. В очереди отображаются статус, «Стоп» и «Повторить» при недоступном продолжении. Остановка подбора сохраняет очередь. Новый ручной запуск музыки отменяет старую волну.
- **Подсказки коллекции:** внизу пользовательского плейлиста и «Любимых» появляются рекомендации с прослушиванием, добавлением, обновлением и меню трека. Состав коллекции определяет контекст подбора. Уже добавленные треки исключаются; пустая коллекция показывает пояснение.
- **Новизна:** на главной в «Для тебя» и в настройках плеера доступен выбор «Знакомое / Баланс / Больше открытий». Режим сохраняется в `personalization.recommendation_mode`, участвует в ранжировании и ключах кеша. При неудачном сохранении прежний режим остаётся выбранным.
- **Объяснения:** движок возвращает `recommendation_reason` на основе связи с опорными артистами, избранным, библиотекой или историей. Пояснения отображаются у рекомендаций плейлиста, в очереди волны, общих строках и карточках. Отсутствие доказательств не заменяется выдуманным объяснением.

## Границы и согласованность

Исходный трек остаётся первой опорой волны. Для следующих порций используются максимум два недавно проигранных подтверждённых трека волны разных артистов. Сбор кандидатов ограничен общим бюджетом 12 секунд. Подтверждённая связь только через дополнительную опору получает меньший вес. Это позволяет искать свежие треки после исчерпания исходного набора; доступность продолжения зависит от источников.

Волна исключает очередь, недавние треки, дизлайки и скрытых артистов. Смена режима обновляет сгенерированные будущие записи, сохраняя текущий трек и ручные добавления. Отрицательная обратная связь удаляет соответствующие будущие записи. Запросы имеют идентификаторы, тайм-ауты и защиту от поздних ответов. Добавление порции атомарно проверяет версию очереди и текущую запись.

API `get_playlist_recommendations(playlist_id, max_results=10, request_id=None)` принимает также `'favorites'`. Завершение приходит через `playlist_recommendations_ready` с `playlist_id`, `request_id`, `tracks` и необязательным `error`.

API `get_track_wave` получил необязательный пятый аргумент `continuation_tracks`; прежние вызовы поддерживаются. `add_tracks_to_queue` получил необязательные `expected_entry_id` и `revision`. Публичный мост остаётся явно ограниченным `PUBLIC_METHODS`.
